| 40 | 2026-10-24 | Restore points and rollback: every change Patch Pilot makes to a user file goes through `patchpilot_local::restore::apply_changes` and nothing else. It refuses while the DAW the files belong to is open (process list via `tasklist` / `ps`; if the list can't be read it assumes the DAW is open), saves each target file's current bytes (or "didn't exist") to a content-addressed blob store in app data (`blobs/<2 hex>/<62 hex>`, BLAKE3, files up to 64 MB), records a restore point (schema v4: `restore_points` + `restore_point_files` with before/after hashes and the machine's latest scan), then writes each file to a temp file beside it, fsyncs and renames it over the target. Files already as requested are skipped; if a write fails the earlier ones are put back and the restore point dropped. Undo writes the saved bytes back (or removes files the change created) through the same path, so an undo is its own restore point and can be undone. No retention limit yet: blobs are small text files and deduplicated. Plug-ins are never uninstalled or reinstalled by a rollback; the history only lists them. | Rules 4 and 5 in one place that every writer shares (Bring over, Ableton, Reaper paths), so nothing can write without a way back; undo-as-a-change keeps history append-only. | Proposed |
